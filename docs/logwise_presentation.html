02 — SCOPE & ASSUMPTIONS
What we know.
What we assume.
What we don't.
Every solution is built on assumptions. Being explicit about them separates an engineer from a guesser.
SCOPE: IN vs OUT
✓ In Scope (v1)
macOS app logs — standard timestamp/level/component format
macOS Unified System Log (log show output)
Apple crash reports (.ips / .crash format, ARM64 + x86)
8 macOS-specific failure signatures (Sandbox, AMFI, Keychain, VPN, SQLite, Jetsam)
Offline / air-gapped operation via rule-based fallback
Claude API for causal chain reasoning (optional)
Single-device, post-hoc log analysis
× Out of Scope (v1)
Real-time log streaming from live devices
Cross-device fleet correlation
Windows / Linux / iOS logs
Automatic MDM remediation push
User behavior analysis or telemetry
SIEM integration (Splunk, Datadog, Elastic)
Logs requiring authentication or VPN to retrieve
ASSUMPTIONS REGISTER
App uses structured logging
Logs follow timestamp · level · component · message. Apps using os_log or custom structured loggers work out of the box.
Known ✓
macOS system log is exportable
log show requires admin access. IT must export it or the endpoint must be temporarily accessible.
Known ✓
Logs are complete & un-truncated
Log rotation may have purged relevant entries. If failure predates the oldest log line, root cause is invisible.
Assumed ⚠
Timestamps are synchronized
Timeline correlation depends on clock accuracy. MDM-managed machines are fine. Manually configured ones may drift.
Assumed ⚠
Failure is reproducible/ongoing
We analyze a snapshot. A one-time fluke (race condition, transient network blip) may match signatures but not recur.
Assumed ⚠
App version matches parser format
Older app versions may use different log formats, breaking the regex parser. Version detection needed for fleet-wide deployment.
Risk ✗
AI output is always correct
Claude synthesizes, not verifies. Confident causal chains may be wrong if underlying signatures are mismatched. Human review required before executing remediations.
Risk ✗
8 signatures cover the problem space
Novel failures — new macOS APIs, custom MDM configurations, third-party driver issues — require new signatures to be written manually.
Risk ✗

KEY CORRECTNESS PROPERTIES
🔁
Idempotency
Same log files always produce the same output. No randomness. Critical for reproducible incident reports and regression testing.
🛡️
Zero False Positives
All 8 signatures explicitly tested against a clean "healthy" log. None fire on normal operation. Signal-to-noise ratio is the whole point.
🌐
Graceful Degradation
Garbage input, empty files, missing crash reports, truncated logs — none crash the pipeline. Every edge case tested explicitly.
